# متطلبات النظام — Mini E-Commerce Order & Shipment Tracking

## 1. نظرة عامة

نظام مبسّط لمتجر إلكتروني واحد: العميل يتصفح الكتالوج، ينشئ طلبًا متعدد المنتجات، ويتتبّع حالته وشحنته. المدير يدير المنتجات والمخزون، ويعالج الطلبات خلال دورة حالات صارمة، ويدخل بيانات الشحن، ويطّلع على تقارير أساسية.

النسخة 1.0 (MVP) — مشروع جامعي (PBL)، مستوى متقدم.

## 2. التقنيات

| الطبقة | التقنية |
|---|---|
| Backend | Python 3.11+ · FastAPI · Pydantic v2 · SQLAlchemy 2.x (sync) · psycopg 3 · Alembic · PyJWT · bcrypt |
| Frontend | React 18 · Vite · TypeScript 5 (strict) · React Router v6 · Axios · TanStack Query v5 · React Hook Form + Zod · Tailwind CSS · Recharts |
| قاعدة البيانات | PostgreSQL 15+ |
| الاختبارات | pytest + HTTPX (Back) · Vitest + RTL + MSW (Front) |

## 3. القيود الملزمة

1. أربعة جداول فقط: `users`, `products`, `orders`, `order_items` + ENUM `user_role` + SEQUENCE `order_number_seq`.
2. المعمارية `Router ← Service ← Model` مع `Schema` للتحقق، وبدون طبقة Repository.
3. SQLAlchemy بنمط sync، ونقاط النهاية بـ `def`.
4. المال `Decimal` / `NUMERIC(12,2)`، ويُرسل في JSON كنص. لا `float`.
5. كل تغيير في قاعدة البيانات عبر Alembic؛ لا `create_all()` في الإنتاج.
6. الكود والتعليقات بالإنجليزية، ونصوص الواجهة في ملفي ترجمة JSON (`ar.json`, `en.json`) مع دعم RTL وLTR.
7. لا أسرار في الكود — متغيرات بيئة و`.env.example` فقط.

## 5. دورة حياة الطلب

`PENDING → CONFIRMED → PACKED → SHIPPED → OUT_FOR_DELIVERY → DELIVERED`

الإلغاء: `PENDING` (العميل أو المدير)، `CONFIRMED`/`PACKED` (المدير فقط). أي انتقال آخر ← 409 `INVALID_STATUS_TRANSITION`.

قواعد: كل انتقال داخل Transaction مع قفل الصف `FOR UPDATE`، وحدث جديد في `tracking_events`، و`SHIPPED` يتطلب ناقلًا ورقم تتبع فريدًا، و`DELIVERED` يعلّم طلب `COD` كـ `PAID`، و`CANCELLED` يعيد المخزون مرة واحدة فقط.

## 6. قائمة الميزات (MVP)

- تسجيل عميل/دخول JWT (Access Token فقط، 30 دقيقة) وإدارة مستخدمين للمدير.
- كتالوج منتجات: بحث، تصنيفات، فلتر سعر، ترتيب، Pagination، وتمييز الكتالوج العام عن لوحة المدير.
- سلة في المتصفح (`localStorage`) وCheckout بمفتاح Idempotency إلزامي.
- إنشاء طلب مع حجز مخزون آمن، حساب أسعار وإجماليات من الخادم، ومنع الطلب الزائد.
- تتبّع الطلب (Timeline) وحالات الشحن والتسليم والإلغاء.
- تقارير المدير: لوحة معلومات، مبيعات، أكثر المنتجات مبيعًا، وعدد الطلبات لكل حالة.
- واجهة عربية RTL متجاوبة، وتصميم Linear-Inspired Minimal SaaS.

## 7. خارج النطاق

الدفع الحقيقي، تكامل الناقلين، المرتجعات، الكوبونات، المراجعات، الإشعارات، تعديل الطلب بعد إنشائه، Refresh Token، وتتبّع عام بدون حساب.

## 8. معايير القبول

تفصيلها في القسم 17 من وثيقة المواصفات، وأهمها: لا مخزون سالب، لا طلب مكرر بنفس المفتاح، تسلسل حالات صارم، إعادة مخزون مرة واحدة، تقارير تستبعد الملغاة، نجاح `typecheck` و`lint` والاختبارات، وتشغيل المشروع من بيئة نظيفة.
